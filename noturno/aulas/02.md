# Oficina de Git/GitHub: Histórico, Branches, Merge, Rebase, Tags, criação de repositórios, configuração do Git, Push e Pull.



## Histórico



O histórico do Git é o registro de todas as alterações feitas em um projeto por meio dos commits. Ele permite visualizar como o projeto evoluiu ao longo do tempo, mostrando:

- quem fez cada alteração;
- quando ela foi feita;
- qual foi a mudança realizada.

### Comandos

| Comando | O que faz |
| ------- | --------- |
| `git log` | exibe o histórico completo dos commits |
| `git log --oneline` | exibe o histórico resumido dos commits |



## Branches

### O que é

Uma branch é uma linha de desenvolvimento independente dentro de um repositório Git. Ela permite fazer alterações no projeto sem modificar diretamente a branch principal (`main`).

### Comandos

| Comando | O que faz |
| ------- | --------- |
| `git branch` | lista as branches existentes |
| `git branch <nome-da-branch>` | cria uma branch (sem trocar para ela) |
| `git switch <nome-da-branch>` | troca para uma branch que já existe |
| `git switch -c <nome-da-branch>` | cria uma branch nova e já troca para ela |

> Cuidado: `git switch nome` sozinho **não** cria a branch. Se ela não existir, o Git devolve um erro. Para criar, use o `-c`.



## Merge

### O que é

O merge é o processo de juntar as alterações de uma branch em outra. Ele é usado, por exemplo, quando uma funcionalidade foi desenvolvida em uma branch separada e agora precisa ser integrada à branch principal (`main`).


### Comando

| Comando | O que faz |
| ------- | --------- |
| `git merge <nome-da-branch>` | integra a branch atual com a que você escolher |

O merge sempre acontece **na branch que vai receber** as alterações. Para integrar a `feature-login` na `main`:

```
git switch main
git merge feature-login
```

> Se a `main` não tiver andado desde que a branch foi criada, o Git só "avança" a `main` até o último commit da branch (isso se chama *fast-forward*), sem criar o commit de junção. E se as duas branches mexeram no mesmo trecho de um arquivo, o Git pede para você resolver o conflito manualmente.


## Rebase

### O que é

O rebase também serve para integrar o trabalho de uma branch em outra, mas por um caminho diferente do merge. Em vez de criar um commit de junção, ele pega os commits da sua branch e os coloca sobre uma nova base.

O objetivo é deixar o histórico mais linear e organizado.

### Comando

| Comando | O que faz |
| ------- | --------- |
| `git rebase <nome-da-branch>` | integra a branch atual com a que você escolher, colocando os commits dela sobre essa nova base |

>Evite utilizá-lo em projetos em que há mais de uma pessoa trabalhando em uma outra branch. Na maioria dos casos, opte pelo Merge.

## Tags

### O que é

Uma tag é uma referência usada para marcar um ponto específico no histórico de um projeto. Ela é muito utilizada para identificar versões importantes, como `v1.0.0`, `v2.0.0` ou uma versão pronta para publicação.


### Comandos

| Comando | O que faz |
| ------- | --------- |
| `git tag` | exibe a lista de tags |
| `git tag <nome-da-tag>` | cria uma tag no commit atual |
| `git tag <nome-da-tag> <hash-do-commit>` | cria uma tag em um commit específico |
| `git show <nome-da-tag>` | mostra as informações da tag |


## Tutorial de como criar um repositório no GitHub e subir os arquivos do seu computador para ele. 

### Passo 1: criar o repositório no GitHub

1. Entre no site do GitHub, na sua conta.
2. Clique em criar um novo repositório e dê um nome ao projeto.

### Passo 2: configurar o Git

Em um terminal, configure as suas informações no Git:

```
git config --global user.name <Seu-usuário-no-Github>
git config --global user.email <seuemail@email.com>
```

>O `--global` faz a configuração funcione para todos os repositórios do seu computador.

### Passo 3: o primeiro push

Vá para a pasta que você deseja colocar no repositório e digite os comandos abaixo, em ordem:

```
git init
git add .
git commit -m "<commit>"
git remote add origin https://github.com/SEU_USUARIO/meu-projeto.git
git branch -M main
git push -u origin main
```

| Comando | O que faz |
| ------- | --------- |
| `git init` | inicializa um repositório Git na pasta atual |
| `git add .` | adiciona todos os arquivos modificados à área de staging |
| `git commit -m "<commit>"` | registra um commit com a mensagem entre aspas |
| `git remote add origin <url>` | conecta a pasta ao repositório do GitHub (`origin` é o nome que damos a esse endereço) |
| `git branch -M main` | renomeia a branch atual para `main` |
| `git push -u origin main` | envia a `main` para o GitHub e lembra esse destino para os próximos envios |

Ao executar o `push`, uma janela pede para você logar na sua conta do GitHub. Logue e se der tudo certo, o push será realizado.

### Enviando novas alterações

Depois do primeiro push, sempre que quiser realizar alterações no seu repositório, digite os seguintes comandos:

```
git add .
git commit -m "<commit>"
git push
```

> Nota: caso queira adicionar apenas um arquivo específico, use `git add <nome-do-seu-arquivo>`.

### Pull

Caso queira adicionar ao seu repositório local arquivos que existem apenas no GitHub, digite:

```
git pull
```
O Git baixa os arquivos novos e atualiza a sua pasta.
